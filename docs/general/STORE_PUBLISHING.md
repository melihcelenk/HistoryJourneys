# Publishing: web and Microsoft Store

History Journeys is a Progressive Web App (PWA). The same build runs in the
browser and, packaged, as a full-screen application from the Microsoft Store.

## What is already in place

- **Web manifest** (generated by `vite-plugin-pwa`, configured in
  `vite.config.ts`): name, `fullscreen` display, theme colors, the
  `games` and `education` categories, and icons at 192 and 512 pixels plus a
  maskable icon (`public/icons/`, generated by `scripts/build-icons.py`).
- **Service worker**: precaches the application, fonts, map data and the
  content database, so the application works offline after the first visit.
  This is covered by an end-to-end test.
- **Relative asset paths** (`base: './'`): the build works from any folder of
  any static host and from inside a package.
- **No user data**: nothing to declare beyond "no data collected" in the store
  privacy section.

## Publishing on the web

1. `npm run build`
2. Upload the contents of `dist/` to any static host that serves HTTPS
   (GitHub Pages, Cloudflare Pages, Netlify). A PWA requires HTTPS.

## Publishing on the Microsoft Store

The Store accepts PWAs packaged as MSIX. The package is a thin shell that opens
the hosted application, so the web version must be published first.

1. Publish the web version (above) and note its URL.
2. Register as an app developer in
   [Partner Center](https://partner.microsoft.com/dashboard) and reserve the
   application name. Partner Center then shows three values under
   *Product identity*: the package ID, the publisher ID and the publisher
   display name.
3. Open [PWABuilder](https://www.pwabuilder.com), enter the URL of the web
   version and choose *Package for stores → Windows*. Enter the three values
   from Partner Center. PWABuilder returns an `.msixbundle` and a `.classic`
   package.
4. In Partner Center create a submission and upload the packages. Fill in the
   store listing: description, screenshots (the files in `tmp/screens/` after
   `npm run test:e2e` are a good start), the category *Games* or *Education*,
   the age rating questionnaire, and the privacy statement.
5. Submit for certification.

## Before the first submission

- Replace the generated icons with final artwork if desired; the Store listing
  also needs a 300×300 logo and at least one screenshot of 1366×768 or larger.
- Decide the category (*Games → Educational* matches the product best).
- A privacy policy URL is required by the Store even when no data is
  collected; a short static page stating this is sufficient.

## Later options

- **Desktop shell** (Tauri or Electron) if a store or platform requires a
  native package rather than a PWA. The application needs no change: it is
  static files with relative paths.
- **Steam** requires a native executable; the same shell would be used.
